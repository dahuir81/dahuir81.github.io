结论

你的判断对了一半，但结论反了

对的一半：Mac Studio 对「7×24 常开网关」这个角色确实没必要 —— 但接替它的应该是 Mac mini，不是 MacBook Pro。

反的一半：「M5 Max 性能超过 M3 Ultra」是事实，但那比的是上一代 Ultra。同代对位，M5 Ultra 的内存带宽是 M5 Max 的 2 倍、内存上限是 4 倍。跑分超过 ≠ 模型能力超过。

我的推荐：不要换，加一台。现有 Mac mini M4 继续当 7×24 网关（它本来就是标准答案），新增一台 MacBook Pro M5 Max 128GB 当移动工作站 + 按需本地大模型。两台分工，比一台顶配干两件事更划算、更稳。

一、先纠正一个关键误判

你现在这台 Mac mini（M4 / 16GB / 120GB·s⁻¹ 带宽）为什么跑不了本地大模型，不是 CPU 慢，是带宽墙。这个物理规律决定了后面所有结论，所以先讲清楚。

大模型推理的硬约束

生成每个 token，GPU 都要把整个模型的权重从内存里完整读一遍。所以解码速度的理论上限就是一个除法：

tok/s 上限 ≈ 内存带宽 ÷ 模型权重大小

算力（GPU 核心数）在这里几乎不起作用 —— 这是内存带宽游戏，不是 GPU 游戏。

当场算一遍

70B 模型 4-bit 量化后权重约 42GB。代入公式：

芯片内存带宽70B Q4 理论上限实测参考可用性
M4（你现在的 mini）120 GB/s≈ 2.9 tok/s内存只有 32GB，直接装不下不可用

「M5 Max 超过 M3 Ultra」这句话要拆开看

Geekbench Metal 跑分：M5 Max 30,000+ vs M3 Ultra 27,691 —— 确实超了，但这说明的是单代架构进步很大，不代表 M5 Max 强过同代的 M5 Ultra。

看带宽：M5 Max 614 GB/s，M5 Ultra 1,200 GB/s。看内存：M5 Max 上限 128GB，M5 Ultra 上限 512GB。

跑分是峰值算力，模型能力看的是带宽 × 容量。这两件事在 Mac 上恰好是分开的。

三、MacBook Pro 当常开服务器：四个硬伤

关键事实：MacBook Pro M5 Max 和 Mac Studio M5 Max 是同芯、同带宽、同内存上限。差别不在算力，在形态。而形态恰恰决定了它适不适合「7×24 挂在墙上跑 OpenClaw」。

① 电池是纯负债

长期插电保持 100% 是锂电池最差工况。macOS 有优化充电，但电池仍是损耗件。

Studio / mini 根本没这个部件，也就不存在这个问题。

② 散热余量小 → 必降频

本地大模型推理是典型的持续满载负载。笔记本散热余量远小于 Studio 的大体积风道。

合盖（clamshell）运行散热更差。

③ 你为闲置功能付了钱

7×24 常开的机器不需要屏幕、键盘、触控板、电池 —— 这些占笔记本成本的很大一块。

历史参照：M4 Max 世代，Studio 起价 $1,999，同芯 MacBook Pro 14" 起价 $3,199。

④ 可移动 = 不可靠

网关被搬去客厅、被合盖、忘了插电 —— 你的定时任务、消息通道、博客自动发布就断了。

服务器角色的第一要求是「一直在那儿」。

但反过来说，MacBook Pro 也有它不可替代的地方

一台机器两份用途（移动办公 + 本地模型）、性能和同价 Studio 不差、出差也能跑。要判断的不是「笔记本好不好」，而是「你要的是不是一台能搬走的机器」。

五、我的推荐：不要换，加一台

组合方案：现有 Mac mini 留守 + 新增 MacBook Pro M5 Max

Mac mini M4（16GB） —— 继续当 7×24 网关。它的负载是消息路由、定时任务、记忆检索，功耗低、静音、已经在稳定运行。这是它的最优角色。

MacBook Pro M5 Max 128GB —— 你的主力工作机 + 按需本地大模型。需要跑 70B 的时候开机接上局域网，跑完合盖睡眠；日常写东西、做分析、带出门都用它。

为什么这样分：两者的故障域完全隔离。笔记本睡眠不影响定时任务；网关被搬走不影响你干活。而且你不需要为一个「偶尔才跑一次」的大模型能力，买一台 24 小时通电的贵机器。

为什么不推荐「一台 MacBook Pro 全包」

  • 你会失去 7×24 的稳定性 —— 笔记本合盖、休眠、带出门，网关就断
  • 你会为一个大部分时间闲置的功能，付电池 + 屏幕 + 键盘的钱
  • 你会让一块电池长期处于最差工况
  • 而保留 mini 做网关，成本几乎为零 —— 它已经在那儿了

为什么不现在冲 M5 Ultra

  • $5,499 起（国行约 ¥40,999 量级），是 M5 Max 的两倍多
  • 512GB 顶配要等到 2026 年 10 月下旬才发货
  • 128GB 跑 70B Q4 完全够用，这个档位的模型两年内仍是主力
  • 除非你有明确的「跑 120B+ 本地模型」需求，否则先别上。

六、如果决定动手，分三步走

第 1 步 · 先证明你确实需要（0 元）

在现有 Mac mini 上装 Ollama 或 LM Studio，跑一个 7B–8B 的量化模型（约 5GB，16GB 内存放得下）。实测它在你这台机器上的真实速度和可用性。

出口标准：你能说清楚「本地模型要拿来干什么、多久用一次、能不能接受那个速度」。说不清楚，就先别买 —— 云端 API 现在又便宜又快。

第 2 步 · 明确用途再定配置

如果验证下来是「偶尔用、要移动」→ MacBook Pro M5 Max 128GB。

如果是「常驻、跑后台任务」→ Mac Studio M5 Max 128GB，网关继续留在 mini 上。

如果只是「偶尔试玩」→ 什么都不用买，继续用云端 API。

第 3 步 · 买之前确认三个数

① 内存必须一步到位（焊死的，买了不能升）；② 确认是 M5 Max 而不是 M5 Pro（差一倍带宽）；③ 国行价格和发货时间以 apple.com.cn 为准，别按美元换算。

七、第四条路线：懒猫 AI 算力舱（英伟达 CUDA 阵营）

前面三条路都是苹果。现在补第四条 —— 它不是 Mac 的竞品，而是另一套物理规律：用英伟达芯片 + 本地软件栈，把「私有 AI 服务器」做成一台可以买回家的家电。

先清一个常被搞混的事实：它既不是 x86，也不是显卡台式机。新款算力舱是 Arm 架构 CPU（Neoverse-V3AE）+ 英伟达 Jetson 平台，预装 Ubuntu；上一代用的是英伟达 Orin 平台。宣传里的「275T / 2070T」是 INT8 稀疏口径的 AI 算力，不能拿去跟台式机的 FP16 数字直接比。

结论

现在不值得买，但值得盯住

一句话：懒猫算力舱不是 Mac 升级的替代方案，它补的是「Mac 做不到的那一块」。你现在的需求不在那块拼图里 —— 所以现在不买；但一旦用法变成「团队共享 + 大批量多模态处理 + 数据绝对不能出门」，它是目前最锋利的一台机器。

算账最狠的一句：128GB 顶配 + 微服套装约 ¥3.5 万。这笔钱按每月 200 元的云端 API 用量，够付 14 年。硬件只在「量足够大」和「隐私是硬需求」两个条件同时成立时才划算。

三个要打折扣的宣传口径

① 「一天 0.3 元电费」偏乐观。按模组 40–130W 反推：0.3 元/天 ≈ 约定 21W 常态功耗。实测空载 40W 约 0.6 元/天，满载 130W 约 1.9 元/天。方向对（仍是同级 GPU 台式机的 1/3–1/5），数字别当真。

② 「31.84 tok/s」不是 70B 的成绩。Qwen3-Coder:30B 是 MoE 模型，每次只激活一小部分参数，所以快 —— 这是 MoE 的功劳，不是带宽的功劳。别拿它推断 70B 稠密模型的速度。

③ 「275T / 2070T 不虚标」说的是口径，不是性能。那是 INT8 稀疏算力，稠密 FP16 要打大折扣。真正决定大模型手感的是带宽：273 GB/s。

4. 值不值得买：两个清单

✅ 适合买
  • 团队 / 工作室共享：一台机器全家设备（电脑、平板、手机）共用一套算力，人越多越省
  • 多模态批量流水线：一天几百上千张图、成批视频转写、整柜 PDF 翻译 —— 这些任务按云端用量计费会非常贵
  • 数据绝对不能出门：合同、投研底稿、行业资料、会议录音，本地算完不联网
  • 需要 CUDA 生态的开发 / 研究者：HuggingFace 下模型直接跑，Jupyter 一键装，不做移植适配
  • 想把 AI 当家里水电用的人：不看 token 计数，用量越大越划算
❌ 不适合买
  • 只有翻译 / 摘要 / 问答这类轻需求：云端 API 每月几十到两百元，¥3.5 万硬件要十几年才回本
  • 需要移动办公的人：2.3kg 方盒 + 必须插电，物理上带不出去
  • 把 macOS 生态当命的人：它是 Ubuntu，AirDrop、Time Machine、Final Cut 那套生态一律没有
  • 在意二手残值的人：小众硬件无成熟二手市场，Jetson 平台一换代价值就跳水
  • 想「一台顶所有」的人：单买算力舱只是台 Ubuntu 电脑，全套 AI 应用要再买微服配套
  • 把它当 Mac 替代方案的人：它替代不了 Mac，它只补 Mac 缺的那一块

用途现有 Mac mini M4 / 16GB还能撑多久

① 你的 AI 用量从「个人偶尔」变成「每天成批」—— 生图、转写、翻译、检索全面跑起来；
② 你有数据不能出门的硬约束（客户资料、投研底稿、会议录音）；
③ 要让家里 / 团队多台设备共享同一套算力；
④ 你要跑某个只有 CUDA 才有的模型或工具链。

四条都不成立，这 ¥3.5 万就先别花。

八、第五条路线：NVIDIA DGX Spark（$4,699 的桌面超算）

第七章的懒猫算力舱之后，再补第五条路 —— 英伟达亲自下场做的那台。它不是 Mac，也不是「厂商基于 Jetson 攒的盒子」，而是英伟达自己出的个人 AI 超算，前身是 2025 年 CES 上公布的 Project DIGITS。

先隔离一个最容易搞混的点：DGX Spark 和懒猫 AI 算力舱是两家公司的两台不同机器。它们唯一重合的数字是内存带宽 —— 都写着 273 GB/s。这不是巧合，是同一代 256 位 LPDDR5X 内存总线的物理上限；但芯片、软件栈、定位、价格全都不同，不能当成一台机器来比。
结论

现在不值得买：它是开发者的原型沙盒，不是生产推理服务器

一句话：DGX Spark 卖的是「CUDA 官方栈 + 128GB 统一内存 + 200G 组网」这三件套，强项在微调和原型开发，不在单机推理速度。它的推理速度被 273 GB/s 锁住，和懒猫算力舱是同一档。

算账：2026 年 2 月涨价后 $4,699（约 ¥3.4 万），与懒猫 128GB 顶配 + 微服套装（约 ¥3.5 万）几乎同价。这笔钱按每月 200 元云端 API 用量，同样够付十几年。

九、一台 DGX Spark 到底能跑什么模型

第八章讲了 Spark 值不值得买。这一章回答更具体的问题：买回来，它能跑什么？全部答案由两条算式推出，先记住它们。

① 容量账 —— 决定「装不装得下」

权重占用 = 总参数量 × 量化字节数

可用预算 ≈ 128GB − KV Cache − 激活/缓冲 − 系统开销 ≈ 100–115GB（实用上限）

⚠️ MoE 模型必须按「总参数」算容量，不是激活参数。这是最常见的误判：一个 235B-A22B 的模型，仍要占 235B 的容量，220 亿激活只决定算得快不快，不决定占多大。

② 速度账 —— 决定「跑得多快」

decode 上限 ≈ 273 GB/s ÷ 权重占用(GB)

实际速度 ≈ 上限 × 40–70%（kernel 效率）

这张表里最重要的一行是「273 GB/s」。它不到 RTX 5090（约 1,792）的 1/6，不到 M3 Ultra（819）的 1/3。Spark 的全部优缺点都从这一行长出来。

4. ⚠️ 官方基准表里的一个坑

把 NVIDIA 官方技术博客表 4 拉出来交叉核对时，发现内部数据自相矛盾：

模型精度官方标称 decode
Llama 3.1 8BNVFP438.65 tok/s
GPT-OSS-20BMXFP4282.74 tok/s
GPT-OSS-120BMXFP4755.37 tok/s ← 比 20B 还快 2.7 倍？

唯一合理解释是：这张表的「token 生成吞吐量」混用了单流（BS=1）和聚合吞吐两种口径，且未统一标注。

结论：NVIDIA 官方基准表不能直接横向比。采购决策必须落到具体模型 + 具体框架 + 具体量化 + 具体 batch上自己测。这也解释了为什么社区数据差异能到 10 倍以上 —— 测法不同，结论就不同。

5. 最反直觉的一点：MoE 逆袭

这是全章最重要的发现：

Llama 3.1 70B（dense, FP8）GPT-OSS 120B（MoE, MXFP4）
总参数70B120B
权重占用~70GB~60GB
实测 decode2.7 tok/s~18–45 tok/s
参数多 71% 的模型，跑得快 7–16 倍

原因：MoE 每个 token 只激活部分专家，实际读取的权重少得多；而 dense 模型每个 token 都要把全部权重读一遍。

所以在 Spark 上选模型的正确姿势是：优先 MoE，避开大 dense。这跟「买显存卡」的直觉完全相反。

7. 一句话判断

Spark 卖的不是速度，是「单机能装下」

该买：要跑 70B–200B 模型且不想上云、不想组多卡；跑 MoE 大模型（GPT-OSS-120B、Qwen3.5-122B、Nemotron 120B）——这里它无可替代；要 CUDA 做微调；长上下文 Agent（prefill 极快，吃长 prompt 很爽）。

不该买：主力模型在 8B–30B → RTX 5090 快 4 倍还便宜；想要 token 生成快 → Mac Studio 带宽 3 倍；想做训练 → 这不是训练机器；想跑 DeepSeek V4-Pro / Kimi K2 → 要 8 台起步，不如买 API。

十一、一页纸总结

一句话

MacBook Pro 不是 Mac Studio 的替代品，它是另一个用途的工具。你要判断的不是「哪个更强」，而是「你要不要一台能搬走的机器」。

六个数字记住就够

带宽：M5 Max 614 GB/s，M5 Ultra 1,200 GB/s（2 倍）；DGX Spark 与懒猫算力舱同为 273 GB/s

内存上限：M5 Max 128GB，M5 Ultra 512GB（4 倍）

解码公式：tok/s ≈ 带宽 ÷ 模型大小，70B Q4 ≈ 42GB

懒猫算力舱：128GB 顶配 ¥29,899 起、微服 ¥4,999 起 —— 卖容量不卖带宽

Qwen3.8-27B：仅需 16–18GB，却能逼近 284B 的 DeepSeek V4-Flash —— 这是今年门槛下降最快的一条线

DeepSeek V4.1 Flash：552B，官方口径需 2k 卡 —— 个人本地路线到此为止

最优解

别换机器，加一台。mini 留守当网关，MacBook Pro M5 Max 128GB 当移动主力 + 按需跑模型。两台分工，预算花在刀刃上，稳定性还更好。

懒猫算力舱先不买。它不是 Mac 的替代品，是 Mac 做不到那部分的补丁；等「批量多模态处理」或「数据不能出门」变成常态，再花那 ¥3.5 万。

DGX Spark 同样先不买。$4,699（约 ¥3.4 万）买来的是「CUDA 官方栈 + 128GB + 1 PFLOP FP4」，但单机推理速度与懒猫算力舱同档（273 GB/s 下 70B Q4 约 6.5 tok/s）。除非你开始做需要 CUDA 的开发和微调，它没有买点。

最终购买建议：三条路各自的触发条件

要快 → 苹果。带宽 614 GB/s（M5 Max）到 1,200 GB/s（M5 Ultra），70B Q4 能跑 12–18 tok/s，是唯一「跑得动又跑得快」的路线。

要装得下、要 CUDA → DGX Spark 或懒猫算力舱。两者带宽同为 273 GB/s、价格同档（约 ¥3.4–3.5 万）。做开发 / 微调 / 200B 原型选 Spark；做团队共享 + 批量多模态 + 数据不出门选懒猫。

要省钱 → 云端 API。每月 200 元就能把现有两台机器用下去；上面任何一台硬件的钱，都够付十年以上。

回到你的真实处境：Mac mini M4 16GB 当网关负载极轻，再战 3–5 年没问题；MacBook Air M1 16GB 无风扇，本来就不适合长期推理。两台都是 16GB 硬顶 —— 真正的短板是内存，不是芯片。

修正后的最终结论（2026-09-15）

先问自己一个问题：你到底要跑哪个模型？第八章之前的结论是「不该为本地大模型花钱」——那个结论建立在「要跑就得买 128GB 贵机器」这个错误前提上。第十章已经把它推翻了。

修正一：门槛比想象中低得多。想做本地 Agent / 代码助手，Qwen3.8-27B 只要 16–18GB，一台 ¥1.5–2 万的 24GB 显卡机或 32GB 统一内存机器就够了，不用碰 ¥3.5 万以上的设备。能力对标的是 284B 的 DeepSeek V4-Flash（Terminal Bench 73.0 vs 82.7）。

修正二：真要上 128GB，触发条件仍然只有三条。① 目标模型是 70B dense 或 120B+ MoE；② 数据绝对不能出门（合规 / 客户资料 / 投研底稿）；③ 每天成批的多模态处理（生图、转写、翻译、检索）。三条都不成立，那 ¥3.5 万就先别花。

修正三：DeepSeek V4.1 这条线本地直接放弃。官方白纸黑字写着大规模部署需要「2k 卡 GPU」，V4-Pro 要 1.0–1.4TB 权重。这不是钱的问题，是物理问题。这类模型的正确定位是买 API，不是自建。

回到你的真实处境：Mac mini M4 16GB 当网关负载极轻，再战 3–5 年没问题；MacBook Air M1 16GB 无风扇，本来就不适合长期推理。两台都是 16GB 硬顶 —— 真正的短板是内存，不是芯片。而按照新的门槛表，你缺的那块能力和它需要的钱，都比三个月前的判断低了一个档。
